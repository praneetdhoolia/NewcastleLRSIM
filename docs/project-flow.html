Why the design exists

Six changes, one corridor, no separation

The corridor was altered five times in six years, and then the pandemic arrived. Any observed change in patronage or footfall over that window is jointly caused, so the model does not compare 2013 with 2026. It fixes a base year, holds land use, population, behaviour and the non-CBD bus network constant, and varies exactly one thing: the central-city trunk mode.

P5 mechanism

Why the loop has to close

Neither tool spans both layers. MATSim answers whether anyone chooses to ride and how journeys restructure; SUMO answers what the system physically does to everyone else once they do. Run either alone and the answer is circular — feed SUMO 3,000 tram passengers and it will faithfully return 3,000 tram passengers.

Three inputs the proposal called critical were not obtainable and are carried as swept parameters rather than assumed facts: SCATS signal phasing, journey-linked Opal, and measured charging dwell.

The size of that gap is measurable. Turning full transit signal priority on cuts modelled end-to-end run time from 12.00 to 7.45 minutes — a 38% swing that rests entirely on phase data nobody has published. That number is the argument for the data request, and the reason no run-time-dependent finding may be reported as a point estimate.

The road-space externality travels with the scenario. S0, S1, S2c and S6 run on a network variant that gives Hunter and Scott Street their second lane and kerbside parking back, and removes the 14 banned turns. A model that adds the tram without subtracting the road space it took would report a gain that isn't there — which is exactly what B3 exists to catch.

Post-simulation

What gets computed

Raw harvest from both engines, reduced to a common skim, then evaluated against the falsification conditions fixed at P0. The conditions below were set before any data was gathered and cannot be revised after results are seen without a logged entry in DECISIONS.md.

MATSim harvest

demand & behaviour
  • events — full agent trace
  • trips.csv — mode, dep time, travel time, wait, distance
  • legs.csv — per-leg detail including transfer structure
  • pt_stop2stop — boardings, alightings, load profile per link
  • scorestats, modestats, accessibility grids

SUMO harvest

supply & operations
  • tripinfo — duration, route length, waiting time, time loss
  • personinfo — walk and ride legs, per-person time loss
  • stopinfo — dwell start/end, delay, loaded and unloaded persons
  • edgeData — density, occupancy, speed, waiting time

Derived skim

the common currency · ≥30 replications per cell

scenario_id · origin_zone · dest_zone · period · mode → ivt_s, wait_s, walk_access_s, walk_egress_s, n_transfers, transfer_wait_s, fare_aud, gjt_s, gjt_sd_s

gjt_sd_s carries as much weight as gjt_s. A 15-minute-headway service with variable signal delay has a materially different effective cost from its mean run time, so reliability variance is reported as a finding, not averaged away.

B3 is the decisive test, and the one most likely to be neglected. A simulation that models the tram without modelling the lane loss, banned turns, kerbside removal and signal cycle changes on Hunter Street will report a spurious gain. The road-space externality is present in the same run, and B3 is a mandatory reported metric — not an optional one.

Gating the next phase

  1. SCATS phase data — a 38% run-time swing rests on it
  2. Charging dwell field measurement — hours of work, 11% of run time
  3. Journey-linked Opal — to estimate rather than sweep the transfer penalty
  4. Manual OSM correction on the corridor — B3 depends on it
  5. LiDAR DTM for The Hill and Newcastle East

Threats being managed

  • ASC absorption — constants estimated pre-intervention and held
  • Corridor tunnel vision — road-space externality in the same run
  • Parameter-driven conclusions — curves, not point estimates
  • Counterfactual naivety — S0 modernised, not the 2014 service as-is
  • Advocacy drift — §3 pre-registered before any run

Standing rule

  • Every source = assumed row appears in DECISIONS.md with a sweep range
  • Falsification conditions are fixed; any change after results are seen is logged with reasoning
  • The project's value depends on being able to publish a result that vindicates the light rail as readily as one that does not
